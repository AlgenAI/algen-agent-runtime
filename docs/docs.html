Build governed agents. Own the runtime.

Algen Agent Runtime is a typed, provider-neutral Python runtime for deterministic agent execution, policy enforcement, durable state, human approvals, and observable multi-agent workflows.

This release is a pre-alpha, single-node foundation. Secure deployment, infrastructure hardening, and operational controls remain operator responsibilities. Start with the production-readiness and threat-model guides.

One execution contract, end to end

Runtime puts governance in the path of execution instead of around it. Every request, model call, tool operation, approval, checkpoint, and output moves through typed contracts with tenant and user context preserved.

Provider-neutral routing

Normalize capabilities, requests, responses, usage, and failures across local and hosted model providers.

Governance in execution

Enforce policies, budgets, permissions, approvals, idempotency, and verification at runtime boundaries.

Durable by contract

Checkpoint runs and workflows, resume approvals, reconcile side effects, and persist events without coupling to one store.

Evidence built in

Emit structured events, immutable audit records, metrics, traces, and redacted telemetry through OpenTelemetry.

Five-minute offline quickstart

The deterministic mock provider requires no credentials, network access, or paid model calls. This makes the same first run suitable for local exploration and CI.

01

Define configuration

Declare a provider deployment and an agent. Configuration is strictly validated; unknown fields fail fast.

02

Build the composition root

build_container wires runtime strategies and adapters from settings without hiding ownership.

03

Submit a typed run

The request carries agent identity, input, tenant, and user context through every execution boundary.

quickstart.py
import asyncio

from algen_agent_runtime.config.settings import AppSettings
from algen_agent_runtime.orchestration.container import build_container
from algen_agent_runtime.runtime.client import AlgenAgentRuntimeClient
from algen_agent_runtime.types.contracts import RunRequest

async def main() -> None:
    settings = AppSettings.model_validate({
        "providers": {
            "mock": {"type": "mock", "default_model": "deterministic"}
        },
        "agents": [{
            "name": "hello",
            "version": "1.0.0",
            "description": "Offline quickstart agent",
            "system_instructions": "Answer concisely.",
            "default_model": {
                "name": "default",
                "provider": "mock",
                "model": "deterministic",
            },
        }],
    })
    container = build_container(settings)
    try:
        result = await AlgenAgentRuntimeClient(container.runtime).run(
            RunRequest(
                agent="hello", input="Hello",
                tenant_id="quickstart", user_id="local-user",
            )
        )
        print(result.output)
    finally:
        await container.aclose()

asyncio.run(main())
Expected output

Hello — deterministic, credential-free, and suitable for an offline test.

Execution model

The native runtime owns legal state transitions. Strategies can be replaced, but they cannot bypass the execution contract: input policy runs before planning, model routing follows capability discovery, side effects pass through the governed tool executor, and output verification is bounded.

01ValidateIdentity, request, input policy
02PrepareContext and strict plan
03ExecuteModel routing and tools
04VerifyOutput policy and repair
05CommitCheckpoint, audit, response
Durability is the source of truth

Active asyncio tasks are an optimization. Checkpoints, versions, tool reservations, approval states, and workflow fingerprints define recoverable execution.

Configuration

Settings merge in a deliberate order: built-in defaults, YAML files, nested ALGEN_AGENT_RUNTIME__ environment variables, then deployment overrides. Request overrides should be explicitly allowlisted by operators.

agent.yaml
providers:
  local:
    type: mock
    default_model: deterministic

agents:
  - name: assistant
    version: 1.0.0
    description: Governed assistant
    system_instructions: Answer with cited evidence.
    default_model:
      name: default
      provider: local
      model: deterministic

Multi-agent workflows

Runtime-owned DAGs compose agent nodes, deterministic handlers, dynamic fan-out, predicates, joins, bounded loops, repair, and exact-version child workflows. Node outputs remain individually addressable and checkpointed.

Node Purpose Runtime guarantee
agent Invoke a registered agent definition. Typed input/output and child run lineage.
map-agent Fan out over bounded input items. Deterministic collection and concurrency limits.
handler Run trusted application logic. Registered action kinds only.
join Combine upstream evidence. Explicit dependencies and addressable outputs.
child workflow Compose an exact trusted version. Parent/root lineage and duplicate-safe reconciliation.

Agent Manifest UI

Added in 0.1.0a4, the Agent Manifest UI is a Swagger-style visualizer for agent.yaml. It reads validated settings and renders the agent catalog, workflow DAG, provider and model matrix, tools and MCP servers, retrieval stores, and a read-only execution view. Output is self-contained HTML with no CDN dependency.

Shell
algen-agent-runtime ui --config agent.yaml --output agent-ui.html --open

# export-ui is an alias of ui; use '-' to write HTML to stdout
algen-agent-runtime export-ui -c config/agent.yaml -o -
Shell
algen-agent-runtime serve --ui

# GET /agent-ui        interactive page (alias: /ui)
# GET /agent-ui/spec   structured JSON manifest
agent.yaml
api:
  agent_ui_enabled: true
  agent_ui_path: /agent-ui
Keep the served UI internal

The UI route is disabled by default and returns 404 with guidance when disabled. It renders configuration detail, so expose it only on trusted networks and behind your own access controls.

Policies & approvals

Governance is evaluated at explicit boundaries, not inferred from prompts. Input and output policies, model permissions, query permissions, budgets, tool classifications, and human approval decisions remain separately auditable.

Policy gates

Check tenant, user, permission, model, source, purpose, budget, and output rules with stable denial codes.

Durable approvals

Persist pause state before returning control. Resume with attributed approve, reject, or modify decisions.

Tools & MCP

Every callable becomes a typed ToolDefinition. The executor validates arguments, checks permissions, reserves idempotency, handles approval, records outcomes, and redacts results. Side-effecting tools are never response-cached.

Classification Meaning Execution posture
read-only No externally visible mutation. May be cacheable under explicit policy.
idempotent Repeated execution has the same effect. Uses deterministic reservation and replay.
non-idempotent Mutation may be unsafe to repeat. Persist before execution; reconcile interruption.
MCP client Remote tools normalized into Runtime definitions. Wired from Python over stdio and legacy sse. Experimental
MCP client Declarative mcp_servers config over stdio, streamable_http, and legacy sse. Supported

Declarative MCP servers

Since 0.1.0a3, MCP servers are declared in YAML and started with the container. Remote transports go through DNS-pinned safe egress, sensitive headers must be env:// references, and operator tool_policies outrank server annotations, which are distrusted by default.

agent.yaml
mcp_servers:
  - name: local-files
    transport: stdio
    command: npx
    args: [-y, "@modelcontextprotocol/server-filesystem", /workspace]
    allowed_tools: [read_file, list_directory]
    required: true

  - name: inventory
    transport: streamable_http
    url: https://mcp.example.com/mcp
    auth_token_ref: env://MCP_INVENTORY_TOKEN
    allowed_tools: [lookup_item, update_stock]
    tool_policies:
      update_stock:
        side_effect: write
        idempotency: non_idempotent
Stdio servers are unsandboxed

stdio commands run as trusted operator code on the host without process isolation. Declare only commands you control. See the MCP guide for the full schema and trust model.

State & persistence

Ports keep execution semantics independent from infrastructure. In-memory adapters support local use and deterministic tests; PostgreSQL and Redis cover durable records, checkpoints, leases, and expiring session state. Artifact bytes can live in encrypted S3-compatible storage while lifecycle metadata remains transactional.

Layer Default Optional adapter
run records & events In memory PostgreSQL
checkpoints & sessions In memory Redis / PostgreSQL
artifact metadata In memory PostgreSQL
artifact bytes In memory Encrypted S3-compatible storage
retrieval Hashing embedder Registered vector-store adapters

Observability

Runtime emits structured lifecycle events, immutable audit contracts, logs, metrics, and traces. Redaction happens before export. OpenTelemetry and OTLP remain the vendor-neutral baseline; Traccia is an optional lifecycle and identity integration.

Audit is not logging

Diagnostic logs can change for operations. Audit records are stable evidence contracts with identity, correlation, policy, decision, and execution attribution.

Production guide

Pre-alpha does not mean prototype, but it does mean deployment claims must stay narrow. Before serving external traffic, validate the complete operator boundary.

01

Threat-model the deployment

Define trust boundaries for API clients, model providers, tool processes, MCP servers, stores, artifacts, and telemetry exporters.

02

Externalize durable state

Configure production stores, migrations, backups, retention, reconciliation, and tenant-isolation verification.

03

Constrain every egress path

Use secret references, outbound allowlists, TLS verification, safe transports, request limits, and provider-specific timeouts.

04

Prove recovery

Exercise worker interruption, approval resume, duplicate delivery, tool indeterminacy, workflow fingerprint mismatch, and store degradation.

API map

The default composition root is intentionally singular. Public contracts stay provider-neutral; adapters live at the edges.

Package Ownership Status
types Normalized public contracts and identities. Core
runtime Legal state transitions and termination. Core
policies / tools Governance strategies and side-effect control. Core
workflows Typed multi-agent DAG execution. Core
models / persistence Provider and infrastructure adapters. Adapters
mcp Declarative MCP client, transports, and tool mapping. Adapters
frameworks Trusted outer adapters for external frameworks. Registration is explicit; Runtime never auto-dispatches agents into them. Optional
ui Agent manifest spec extraction and static UI generation. Optional
orchestration Default settings-driven composition root. Core
